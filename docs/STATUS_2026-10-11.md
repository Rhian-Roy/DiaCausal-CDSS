## 3. What the submitted system is (one paragraph each)

- **The engine** (`diacausal/causal_inference/`):
  - Compares SGLT2i, DPP-4i and sulfonylurea added to metformin, for one adult with type 2 diabetes.
  - Gives the 6-month HbA1c change with a 95% interval, plus weight and hypoglycaemia.
  - Methods: cross-fitted propensity, AIPW and DR-learner.
  - Abstains: below propensity 0.05, or an interval wider than 1.5.
  - Safety rules from `data/rules.csv` run **before** any estimate.
  - Data: a synthetic India-calibrated cohort only; every parameter in `data/params.yaml` has a source and a status.
- **The evidence search** (`diacausal/rag/`):
  - Licence-gated: 78 passages from WHO 2018 and FDA safety communications.
  - BM25 + TF-IDF, fused with RRF; abstains when coverage is low.
  - Every passage carries source, version, section, page and licence.
- **The pipeline** (`diacausal/orchestrator/`, `POST /api/v1/ask`):
  - Layers in order: input guards → rules → causal engine → retrieval → explanation → output guards → formatter.
  - Returns `AnswerCardV1`.
  - Tracing logs IDs, layer names, codes and times only, never patient values or the question.
- **The writer:**
  - The template quotes passages by default.
  - A local Ollama model can write instead (clinic laptop only), but every draft must pass 7 output checks or the template
    answers.
  - The website never uses an online model.
- **Explanations (XAI):**
  - Exact SHAP drivers of the causal estimate (version C), each with a 95% interval, described as "the estimate is
    larger/smaller for patients with…", never as causes.
  - The XAI-only version A (SHAP + LIME on a predictor) is a baseline shown only in the Analysis tab.
- **The website** (`web/`, https://diacausal.netlify.app):
  - A static phone-first PWA, built from `design/screens-v2/`.
  - The engine, search, guards and explanation run **in the browser** (parity-tested against Python).
  - Supabase sign-in with admin approval and TOTP.
  - Tabs: Patient Details, Investigate, Analysis, Guide, About.
- **The clinic laptop:**
  - `scripts/start_clinic.*` starts the same server on 127.0.0.1:8000 only; no accounts, no internet after setup.
- **The old chat app** (`backend/`, `frontend/`, Docker):
  - Kept and still fully tested (part A of `check_all`), but **not part of the submitted system**.
  - Its deploy guide is the last section of `docs/DEPLOY.md`.
