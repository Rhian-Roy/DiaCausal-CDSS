# Restructure plan: one `diacausal/` package (P10, plan only)

> Research prototype for clinician evaluation; not a marketed medical device; not for unsupervised clinical use.

**Status: written 4 October 2026. Nothing has been moved.** This is the plan for P13 (Member C, Wed 7 to Fri 9 Oct, with steps 9 and 10 after gate G1). It follows the target tree of section 8.3 of [docs/PLAN_2026-10.md](PLAN_2026-10.md). Every old-to-new path is in the tables below and, for **all 610 tracked files of `main` at commit `d744499`**, in [docs/RESTRUCTURE_FILE_MAP.csv](RESTRUCTURE_FILE_MAP.csv) (the two plan files themselves are the only additions and stay put; generated by a script and checked: every file appears exactly once and no two files land on the same path, even ignoring letter case).

## 1. The short version

- **Today** there are three Python code areas at the repo root: `diacausal_engine/` (16 files, the 3-arm causal engine), `diacausal_rag/` (20 files, search and explanations) and `causal_engine/` (12 files, the old 2-arm research code), 24 files at the root (12 of them old research scripts and notebooks) and two apps, `backend/` and `frontend/` (the chat app).
- **Target:** `diacausal/` (api, orchestrator, guards, rag, causal_inference, xai, llm, output, plus `registry.py` and `tracing.py`), `knowledge_sources/` (renamed from `RAG/`), `legacy/` (the old engine, loose scripts and notebooks, and later the chat app), and `tests/` including `tests/e2e/`.
- **Size:** of 610 files, 227 move (51 to `legacy/` early, 132 chat-app files after G1) and the rest stay. 4 big modules are split in a second, separate commit, and one is merged (`INTENDED_USE`).
- **The key safety idea:** the **chat app imports nothing from the engine or the RAG package**, and the **website only uses `web/model.json` and `web/evidence.json`**. So the Python moves cannot break either app, as long as those two exported files come out **byte-identical** after every step (section 6).
- **How it stays working:** old import paths keep working through small **shim files** (section 4) until every caller and document uses the new names (step 9).

## 2. Facts that shape the plan (all checked on `origin/main`)

1. **The chat app does not use the engine or RAG.** `backend/app/pipeline/causal_engine.py` and `rag_retrieval.py` are stubs that return "skipped" (their comments still name the legacy engine). `scripts/check_all.py` tests only the chat app (43 checks); it never imports `diacausal_engine`.
2. **Who imports what:**
   - `diacausal_engine` is imported by `tests/engine` (13 files), `tests/web`, `tests/contract`, `diacausal_rag` (3 files import the dose pattern from `diacausal_engine.recommend`), `demo/streamlit_app.py`, `diacausal/api/schemas` (4 files, because `CausalOutputV1` subclasses the engine's model) and `scripts/make_contract_examples.py`.
   - `diacausal_rag` is imported by `tests/rag` and `tests/web`; the `python -m` commands that name it appear in 25 pages of `docs/` plus `README.md` and `CLAUDE.md`.
   - The legacy `causal_engine` is imported only by `build_notebook.py`, `causal_inference_basics.py`, `diacausal_demo.py`, `smoke_streamlit.py`, `tests/test_causal_engine.py` (all of which move with it) and, by name only in comments, the chat-app stubs.
3. **Code finds its files by arithmetic on `__file__`.** `diacausal_engine/config.py` and `diacausal_rag/ingest.py` define `ROOT = Path(__file__).parent.parent`; `explain.py` reads `prompt.v1.txt` and `ingest.py` reads `corpus/` and `config.yaml` **next to themselves**. A move changes these depths. Only `config.py` keeps the same depth when it goes to `diacausal/config.py`.
4. **Two tests scan the engine code by folder name** (`tests/engine/test_a_cohort.py:102`, `test_b_guardrails.py:101`: "Pima is not used" and "no clinical number in code"). After a move, a scan of the old folder would see only shims and **pass without checking anything**.
5. **Tests patch module attributes** (`monkeypatch.setattr("diacausal_engine.recommend.AUDIT_PATH", ...)`, `rec.AUDIT_PATH = ...`). A shim that only copies names (`from x import *`) would let such a patch miss the real module.
6. **Fingerprints use names and bytes, not folders.** `web/evidence.json` records `corpus_sha`, `sources_sha` and `config_sha` computed from each file's **name and content**, so moving the corpus files, `sources.csv` and `config.yaml` without renaming them leaves the fingerprints, and therefore `evidence.json`, unchanged.
7. **Case-insensitive disks.** macOS (and the Windows CI runner) treat `RAG/` and `rag/` as one folder. Nothing in the plan creates a root `rag/`; `diacausal/rag/` is fine because it is not at the root. `RAG/` becomes `knowledge_sources/`, a different name, so no case-only rename is needed.
8. **Moving `backend/` and `frontend/` is the dangerous move.** They are named in `scripts/setup.py`, `scripts/check_all.py`, the `Dockerfile`, `compose.yaml`, `.dockerignore`, `.devcontainer`, `.github/workflows/check.yml`, `.github/dependabot.yml` and `.gitignore`, and they hold **untracked** things: `backend/.venv`, `backend/.env` (the key that encrypts MFA secrets), `backend/*.db`, `frontend/node_modules`. Hence "after G1".
9. **Section 8.3 names files that do not exist yet** (`input_guards.py`, `hybrid.py`, `query_processing.py`, `dense.py`, `evidence_level.py`, `xai/*`, `llm/prompt_builder.py`, `output/*`, `orchestrator/pipeline.py`, `registry.py`, `tracing.py`). P13 only moves and splits existing code; later prompts create the rest (section 8).
10. **Parallel work.** P15 (input guards, Member D), P16 (query processing, Member B) and P17 (XAI baseline, Member A) start on Wed 7 Oct, the same day as P13. If they edit the old modules, every step below turns into a merge conflict.

## 4. Shim files at the old import paths

A **shim** is a tiny file left at the old path so old `import` lines and `python -m` commands keep working. There are three kinds.

**(a) One module moved whole** (most files): the shim replaces itself with the real module, so `import diacausal_engine.recommend as r` gives the *real* module and patches such as `r.AUDIT_PATH = ...` or `monkeypatch.setattr("diacausal_engine.recommend.AUDIT_PATH", ...)` still reach it:

```python
# diacausal_engine/recommend.py  (shim; removed in step 9)
import importlib, sys
sys.modules[__name__] = importlib.import_module("diacausal.causal_inference.recommend")
```

**(b) A module with a command-line entry point** (`benchmark`, `export_web` x2, `evaluate`, `explain`, `pdf_text`, `sources_table`): the same, plus forwarding for `python -m old.path`:

```python
# diacausal_engine/benchmark.py  (shim)
import importlib, sys
if __name__ == "__main__":
    importlib.import_module("diacausal.causal_inference.benchmark").main()
else:
    sys.modules[__name__] = importlib.import_module("diacausal.causal_inference.benchmark")
```

**(c) A module that was split** (`estimators`, `ingest`, `retrieve`, `explain`): one module cannot stand for several, so the shim names what it re-exports (never `import *`, which would miss underscore names):

```python
# diacausal_rag/ingest.py  (shim)
from diacausal.rag.ingest.chunking import Chunk, chunk_document, split_sections          # noqa: F401
from diacausal.rag.ingest.licence_gate import LicenceError, ingest, is_confirmed, load_sources  # noqa: F401
from diacausal.config import load_rag_config as load_config                                 # noqa: F401
```
Patching through a type (c) shim is **not supported**; the tests that patch only touch type (a) modules (checked), and step 8 moves all tests to the new names before any shim is removed.

**Package shims:** `diacausal_engine/__init__.py` and `diacausal_rag/__init__.py` stay and re-export `INTENDED_USE` and `__version__` from `diacausal`. `uvicorn diacausal_engine.api:app` keeps working through a type (a) shim of `api.py`.

**Shim list:** one shim per old module: 15 engine modules and 7 RAG modules, plus the two `__init__.py` files (24 files in all). **Removal (step 9):** delete `diacausal_engine/` and `diacausal_rag/` only when `git grep -E "diacausal_(engine|rag)"` finds nothing outside `docs/PLAN_2026-10.md`, `docs/AUDIT_2026-10-03.md` and this file, and a full green run has passed on the new names.
